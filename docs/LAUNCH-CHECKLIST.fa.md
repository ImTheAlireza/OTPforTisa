# چک‌لیست نهایی‌سازی و انتشار «سیگنا» — استودیو پارسنا

> وضعیت فعلی: افزونه نسخهٔ **۲.۰.۱**، فازهای ۱ تا ۷ تمام، همهٔ آزمون‌ها و CI سبز.
> نام استودیو **پارسنا** (`parsena.ir`) — دامنه و هاست خریداری شد، منتظر راه‌اندازی.
>
> **کانال فروش: فقط راست‌چین** (فروشندهٔ اختصاصی). سایت پارسنا فقط معرفی و دمو است و
> خریدار مستقیم به صفحهٔ محصول در راست‌چین فرستاده می‌شود؛ پس فروشگاه، درگاه پرداخت،
> اینماد، سرور لایسنس و سرور به‌روزرسانی **لازم نیست**.
>
> راهنما: 👤 = کار شما · 🤖 = کار من (کد/محتوا) · 👥 = با هم · ⛔ = مسدودکنندهٔ فازهای بعد

## قوانین راست‌چین که روی کار ما اثر دارند

منابع: [قوانین ارائهٔ محصول](https://www.rtl-theme.com/designer/)، [استاندارد ارسال محصول](https://www.rtl-theme.com/standard-product/)، [قوانین خریداران](https://www.rtl-theme.com/buyers-rules/)

| قانون | اثر روی ما |
|---|---|
| عضویت فروشنده: مدارک هویتی و بانکی + اسکن امضاشدهٔ قرارداد؛ بررسی تا ۷۲ ساعت کاری | 👤 از همین حالا |
| فروشندهٔ تازه‌کار یک محصول را در آن واحد رزرو می‌کند؛ رزرو افزونه حداکثر ۱۴ روز | بعد از رزرو ۱۴ روز فرصت ارسال داریم ← رزرو را **آخر کار** بزنید |
| لایسنس انحصاری راست‌چین برای فروشندهٔ اختصاصی؛ API از «پیشخوان ← تنظیمات ← دریافت API»؛ مستندات فقط در پروفایل فروشنده | تا حساب فروشنده تأیید نشود، جزئیات API را نداریم |
| «فقط از نسخهٔ جدید لایسنس استفاده کنید» | ماژول لایسنس طبق مستندات جدید |
| لایسنس با «افزونهٔ مدیریت لایسنس راست‌چین» کنار محصول اجرا می‌شود | سیگنا باید کنار آن بی‌دردسر کار کند |
| پیش‌نمایش کاملاً فارسی الزامی؛ برای افزونه: **لندینگ با تست آنلاین** یا **ویدیوی معرفی فارسی**، روی هاست و دامنهٔ خود فروشنده | `parsena.ir/signa` + `demo.parsena.ir` |
| **هر لینک یا راه ارتباط شخصی** در محصول، دمو یا فایل راهنما ← رد محصول | نشانی‌های سربرگ افزونه و هر پیوند به parsena.ir داخل افزونه بازبینی شود |
| پکیج افزونه: پوشهٔ `Plugin` (فایل zip) + `help.pdf` (راهنمای فارسی نصب و راه‌اندازی) | 🤖 ساختار پکیج + راهنمای PDF |
| نیازمندی‌ها (نسخهٔ PHP، حافظه و …) و سازگاری‌ها باید در توضیحات صریح بیاید | متن محصول |
| متن و تصاویر محصول از نظر کپی بررسی می‌شوند | همه‌چیز نوشتهٔ خودمان |
| فروشنده قبل از ارسال و **قبل از هر آپدیت** باید در «محیط استاندارد» (فقط هستهٔ وردپرس + قالب پیش‌فرض) تست کند | `tools/wp-qa` همین کار را می‌کند ✅ |
| با آپدیت وردپرس، ووکامرس یا افزونه‌های اصلی: آپدیت سازگاری **حداکثر یک هفته**، وگرنه توقف فروش | ماتریس CI فعلی ✅ |
| پاسخ پشتیبانی حداکثر ۲۴ ساعت کاری؛ باگ رفع‌نشده یا مغایرت با توضیحات ← بازگشت وجه | پشتیبانی از طریق خود راست‌چین |

> ⚠️ منبع دیگری (غیررسمی) می‌گوید محصول لایسنس‌دار باید کدگذاری (encode) شود و کدگذاری فقط با سرویس راست‌چین مجاز است. این را بعد از تأیید حساب فروشنده در مستندات پیشخوان چک می‌کنیم.

## مسیر بحرانی

```
فاز ۱ (تأیید فروشنده) ──► ۳.۲ لایسنس ──┐
فاز ۲ (هاست) ──► فاز ۵ (لندینگ + دمو) ──┼──► فاز ۶ (پکیج) ──► فاز ۷ (رزرو + ارسال)
۳.۱ حالت دمو + ۳.۴ آزمون واقعی ─────────┘
```

**همین حالا، بدون انتظار:**
1. 👤 درخواست فروشندگی در راست‌چین
2. 👤 حساب‌های آزمایشی سامانه‌های پیامکی و کلیدهای کپچا
3. 🤖 حالت دمو
4. 🤖 پیش‌نویس help.pdf و متن لندینگ

**برآورد کل:** حدود ۲ تا ۳ هفتهٔ کاری. گلوگاه اصلی تأیید حساب فروشنده و مستندات لایسنس است، نه کدنویسی.
